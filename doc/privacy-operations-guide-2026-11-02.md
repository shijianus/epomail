# 个人维护者隐私上线与运营指南

编写日期：2026-11-02。此日期不是政策生效日，也不是任何保存期限的起算日。

本指南用于安排 EpoCanvas Mail 的上线前核对、权利请求和事故处理，不替代对用户的告知文件或专业法律判断。它不是合规认证，不表示已有真实运营者资料、已签契约、已完成线上测试或已经部署。适用法域、处理角色和实际供应商由维护者逐项确认；下列空白模板必须填入事实，不能以勾选或测试数据替代。

本轮应用与检查工具都不能代运营者填入真实身份、签署契约、选择真实处理地区或履行用户请求。向真实用户开放前，适用事项必须实际完成。缺少的事实应保留为未完成，不以品牌名、仓库作者、示例邮箱、空字符串或虚构合同补足。

## 1. 最小职责与材料

个人维护者可以由同一人承担发布、权利请求和事故记录，但应记录联系渠道、定期查看方式，以及自己暂时无法处理时的安排。并非所有服务都必须先取得 ISO 认证、购买保险或聘用专职人员；是否需要特定措施，应依据适用义务、规模、数据敏感性和合同决定。无法判断法源、跨境安排或通知义务时，再寻求针对性专业协助。

上线材料最少分为四项，保存在访问受限的位置，不把真实用户资料、契约全文、凭证或工单附件提交到公开仓库。

| 材料 | 最少内容 | 未完成时的处理 |
| --- | --- | --- |
| 运营者与告知 | 实际负责任的自然人或组织、有效联系渠道、适用的送达资料、实际发布的告知与版本 | 不向真实用户开放；不把产品名当作法定身份 |
| 处理台账 | 本指南第 3 节的逐项记录及证据索引 | 不启用尚未厘清用途或接收方的处理 |
| 供应商与契约记录 | 实际账号主体、服务、处理角色、地区、条款版本、接受或签署证据、未决问题 | 将受影响功能保持关闭；基础服务所需安排未完成时不开放核心服务 |
| 执行记录 | 权利工单、删除验证、事故判断与下一次复核 | 无法履行的承诺不写成已实现 |

供应商网页可用于查阅条款，不能单独证明当前账号已接受适用版本。依据实际受托处理和跨境情形核对所需 DPA、SCC 或其他合法安排；不能把所有供应商一律认作相同角色，也不能把「支持某地区」当作本账号已锁定该地区。

## 2. 按实际功能门槛分阶段开放

### 2.1 配置门槛与人工事实是两回事

公开配置来自 `GET /api/setting/websiteConfig`，成功响应封装为 `{ code: 200, data: { ... } }`。检查工具只读取这一次响应，不调用注册、翻译、删除、导出或管理员写入接口。

| 响应字段 | 本工具的配置要求 | 人工核对边界 |
| --- | --- | --- |
| `legalNotice.operatorName`、`operatorCountry`、`termsVersion` | 必填非空文本，拒绝常见未填写占位符 | 实际运营主体、国家/地区与生效版本不是靠格式判断 |
| `legalNotice.contactEmail` | 必填有效邮箱格式 | 应由实际负责人员接收并能处理请求 |
| `legalNotice.termsUrl`、`privacyUrl` | 必填有效 HTTP(S) URL，HTTP 仅限 loopback | 页面是否可达、是否是本服务实际告知及是否完整，另行核实 |
| `legalNotice.contactAddress` | 若提供须为字符串；不是一刀切必填 | 按适用场景落实送达资料，不统一要求公开个人住址 |
| `legalNotice.recipientsUrl`、`retentionUrl` | 可为空；提供链接时校验其 URL | 未设独立链接不免除接收方、地区、保存依据与实际执行的核对 |
| `registrationReadiness.ready`、`missing` | `ready` 必须严格为 `true`；`missing` 必须是空数组 | API 自述不能盖过法律字段缺项或证明真实事实 |
| `contentProcessing` | 下表四个开关须严格为布尔值；任一启用须有有效 `noticeUrl` | 不请求可选功能，不证明用户已确认或契约已成立 |

| 功能 | 对照配置或请求条件 | 开放前的实际核对 |
| --- | --- | --- |
| 注册与首次建立账号 | `legalNotice`、`registrationReadiness` 以及实际注册开关；预检不替代服务端写入路径的再检查 | 真实身份、联系渠道、告知链接和版本均可用；直接注册及 OAuth 首次建号不能绕过门槛 |
| 自动提取邮件验证码 | `contentProcessing.verificationCodeEnabled`，以及用户的 `privacyPreferences.aiVerificationCode === true` | 分清本地规则处理与远端内容传输；未选择的用户不进入远端可选处理；不是一次注册同意所有 AI 用途 |
| 用户触发翻译 | `contentProcessing.translationEnabled`、AI 实际启用状态、有效 `noticeUrl`；远端请求还需与当前告知匹配的明确确认 | 告知实际接收方、数据范围、用途和撤回方式；取消确认不得发送内容；本地预设模板不等于远端调用 |
| 图片 OCR | `contentProcessing.ocrEnabled`；翻译路径、单次 OCR 选择及相关确认也必须满足 | 核对图片、附件或外链是否被访问、送给谁；不因启用文本翻译就默认同意 OCR |
| 公共翻译后备服务 | 当前版本不提供；`contentProcessing.publicTranslationFallbackEnabled` 恒为 `false`，拒绝保存 `true` | 已移除 MyMemory／Google 公共接口及缺片补译路径；以后恢复功能须另行评估、告知并验证 |
| 转发、第三方存储与第三方 API | 各自服务端功能开关、用户选择、权限与撤销路径 | 内容处理四开关不代表这些功能也安全；逐项核对实际接收方、数据与撤销结果 |

`contentProcessing` 的四个开关必须是明确的布尔值。全部为 `false` 时可以关闭这一组可选内容处理，`noticeUrl` 可以为空。任一功能启用都必须有有效告知 URL；填了 URL 或把开关设为 `true` 仅是配置证据，不证明已经签约。不要为了获得预检成功而打开不需要的功能。

API 中 `ready` 为 `false`、字段缺失或内容不完整时，检查应报告 `notReady` 并退出 1。安全关闭某个可选功能可以是一种上线范围选择，但关闭注册或关闭全部内容功能，不能使缺少真实身份的配置变成就绪。

### 2.2 上线顺序

1. 选定最小服务范围。先列基础邮件、账户与托管所必需的处理，再列验证码提取、翻译、OCR、后备翻译、转发等可选处理。暂时无法完成其接收方或契约核对的可选功能保持关闭。
2. 维护者实际填写运营者身份、可用联系渠道和已发布告知版本，核对对外文案与实际处理一致。身份真实性不能由字符串格式检查代替。
3. 完成计划开放范围的台账、供应商账号/契约/地区核对与保存决定。对第三方仅有宣传说明而无账号级证据的项目记为未确认。
4. 独立完成受控合成测试。使用隔离的本地环境、内存固定响应、合成邮件和可控接收端，不使用真实用户邮件、生产凭证或真实收件人；若另行需要落库，预先安排隔离和清理。合成身份只属于测试夹具，不能写回运营配置。
5. 运行第 7 节只读预检，修复缺项后重查。对于未准备好的真实配置保留退出 1，不新增跳过身份、忽略门槛或强制成功参数。
6. 另外验证门槛实际执行。至少包括缺告知时不能建号、OAuth 首次建号不能绕过、内容处理关闭时不外传、未确认/旧告知请求被拒绝、用户撤回后停止可选处理，以及注销/导出/删除失败能被记录与处理。一次配置响应或 Node 夹具测试不能证明这些运行结果。
7. 由维护者在受限记录中写明范围、日期、证据位置、未决事项及决定。只有实际完成适用的身份、契约和执行准备后，才决定是否向真实用户开放；本轮代码任务本身不执行开放或部署。

发布后，新增接收方、地区或用途、修改通知版本、改变保存策略、开通新功能，以及发生请求或事故失败，都应触发复核，而非只在固定日期检查一次。

## 3. 一张最小处理台账

每个目的或接收方差异较大的数据流单独一行。一个空白表格不是已经建立台账；不得填「同意」两个字就省略其适用前提。

| 记录编号 / 功能 | 具体目的 | 法源及适用理由 | 数据类别与最小范围 | 接收方及角色 | 实际处理/存储地区与证据 | 契约状态、版本及证据索引 | 必要保存依据、起算/结束条件与上限 | 复核周期与变更触发 | 删除验证、结果及日期 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 待填写 | 待填写 | 待判断并记录 | 待盘点；勿贴原始内容 | 待确认；含后备服务 | 未确认，不推定地区 | 未签/待核实/已完成及依据；不得虚构 | 按目的决定并写明可执行条件 | 维护者决定并安排 | 未验证；写明方法及未完成范围 |

可拆分为账户身份、邮件内容/附件、必要安全日志、告知接受记录、权利工单、AI 处理、外部转发等条目。第三方自己的日志、备份或灾备副本要单独确认，不能因为主数据库删除就假定全部副本消失。

### 保存与日志：按目的决定，不抄建议天数

下面是决定方式的例子，不是已实施配置、法定期限或新的对外承诺。真正上线使用前，维护者应填写具体条件、合理上限、清理执行方式及验证结果。

| 示例目的 | 最少可记录内容 | 如何作保存决定 | 如何验证 |
| --- | --- | --- | --- |
| 定位一次可复现的技术错误 | 事件代号、错误类别、时间、必要的去标识关联值 | 故障排除并完成必要验证后删除；如需要滚动排错窗口，说明为何需要并另定明确上限，不无限期留全量日志 | 检查日志平台实际过期/删除配置，并用合成事件观察到期清理 |
| 防止短时滥用 | 窗口计数及确有必要的标识；不含邮件正文、密码或验证码 | 依据实际攻击识别窗口决定；区分计数缓存和调查证据，不能共用无限保存设置 | 观察窗口过期；核对不再需要的关联标识是否删除 |
| 处理权利请求或争议 | 工单代号、行动、日期、结果和必要证据 | 先判断结案后是否仍有明确必要性或义务；必要时限制访问，另定复核和最终删除条件 | 抽查结案记录、延期理由、访问权限与删除结果 |
| 事故调查 | 与事故相关的最少事件证据、决定过程 | 在调查及适用义务需要的范围内保全；隔离于日常调试日志，记录保全解除条件 | 复核保全必要性；解除后验证清理并记录例外范围 |

避免在日志中写入密码、令牌、私钥、会话 Cookie、邮件正文、验证码或完整个人资料。确实需要的证据也应最小化并限制访问。若保存决定尚未配置或清理任务未验证，记录「未实施」而不是把本指南的例子当作既成事实。

## 4. 权利工单：收到日、期限、行动、结果

收到请求后先记录日期和时区，再确认请求范围、适用规则及身份核验的必要程度。不要默认要求身份证副本，更不要索取账号密码。可利用现有受控登录或其他相称方式核验；含邮件或附件的导出物应经受控渠道交付。

| 工单代号 | 收到日/时区与渠道 | 请求类型/范围 | 身份核验方式及完成日 | 适用期限、依据与计算起点 | 到期日及提醒 | 已做行动/日期/负责人 | 结果、交付日与未完成范围 | 延长/拒绝/例外的理由及告知 | 结案与保存复核 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 待填写；不用完整邮箱作编号 | 待填写 | 查阅、复制、更正、停止、删除等 | 仅记录必要的核验结论 | 逐案判断；不能直接套用统一天数 | 待计算并设置 | 待执行 | 未完成，不写成功 | 有则记录事实与依据 | 待安排 |

执行时区分三个阶段。

- 接受请求：告知已收到，不等于已经完成全部请求。
- 停止访问与撤销：核对会话、API 令牌、设备信任、OAuth 及公开分享/转发入口。账号不可登录不等于内容已从所有存储删除。
- 数据处置与核对：逐项确认数据库、KV、邮件/附件对象、删除队列、备份及第三方范围；保留必要的结果证据而非原始数据副本。

当前注销路径中的 `accountDisabled` 或 `cleanupComplete` 不应解读为所有数据物理删除；若返回 `physicalDeletionComplete: false` 或 `deletionStatus: manual_review`，必须继续跟进。遇到 `cleanup_failed`、对象删除队列待处理/失败或第三方未回复时，工单仍有未完成范围；不能把接口接受请求、界面提示成功或空列表当作删除验证。

入站恢复另暂存完整原始 MIME 的服务器端 AES-256-GCM 密文，并在数据库保存所属用户、收件信息、原文哈希、对象定位与到期时间。7 天是应用清理期限，失败重试可能续期；成功入库不立即删除，计划任务分批删除失败时仍会保留。该路径不是附件删除队列，也不是存储层 TTL 保证。实体删除用户前须先清除其原始邮件对象和恢复记录；失败时保留用户及原存储定位，禁止先撤掉自备存储配置。此暂存不在自助 JSON、`.eml` 或 MBOX 导出范围内，导出文件仍须核对重建字段。

导出也应核对实际字段范围、附件是否包含、加密内容是否可读，以及其他存储是否另需处理，不能默认单个导出端点覆盖全部个人数据。`websiteConfig` 无法证明任何个案已完成；上线前用独立合成数据验证，实际工单再记实际结果。

## 5. 事故判断记录

先限制进一步暴露、保全必要证据，再按事实及适用规则判断是否涉及个人数据、是否需要通知、对象和时限。不能因为没有收到用户投诉就写「没有事故」，也不能把一般错误日志自动当作必须对外通知的事故。

| 记录字段 | 待填内容 |
| --- | --- |
| 事件代号、发现时间、知悉时间与时区 | 待填写；保留区别及理由 |
| 发现来源与已确认事实 | 待填写；将推测另列 |
| 影响系统、数据类别、对象与估计数量 | 已确认范围及尚待调查范围 |
| 事件性质 | 未授权存取、披露、遗失、毁损或其他；记录可用性/完整性影响 |
| 立即控制措施、执行时间与结果 | 例如暂停受影响功能、撤销泄漏凭证；不在记录中粘贴凭证 |
| 证据位置、访问控制与必要保全范围 | 存放受限索引；避免复制无关邮件 |
| 通知判断 | 适用规则、是否须通知主管机关/当事人/合作方、理由、待确认问题 |
| 期限与决定 | 起算事实、具体到期日、负责人、延期或无需通知的依据 |
| 实际行动与送达 | 通知内容版本、时间、渠道、收件回执；未送达继续跟进 |
| 修复、验证与结案 | 采取措施、独立验证、残余影响及复核日期 |

单人无法同时调查、修复与判断法律义务时，先停用受影响处理，及时取得必要协助。恢复功能前验证阻断原因已消除，不仅看配置开关重新变为启用。

## 6. 删除验证记录

每次验证最少记录「对象代号、存储位置类别、请求时间、执行方法、实际结果、核对时间、未完成原因、下一步」。不要在验证表中复制用户邮件内容或完整凭证。

| 范围 | 需要的实际证据 | 不能替代证据的状态 |
| --- | --- | --- |
| 访问撤销 | 旧会话/令牌/分享链接不能继续访问；关闭后不再触发可选转发或内容处理 | 仅退出当前浏览器 |
| 数据库与 KV | 已确认目标记录和索引处置结果；异常已处理 | 仅隐藏页面或设置逻辑删除标记 |
| 邮件/附件对象与删除队列 | 对象处置已核对，待处理/失败项有结果；保留重试所需定位信息直至完成 | 仅数据库行消失，或假定队列会自行完成 |
| 第三方与备份 | 实际可用的删除机制、确认/到期证据及不能立即删除的范围、依据和访问限制 | 仅关闭集成开关，或只看主存储已删除 |

## 7. 只读预检工具

从 `D:\Users\Smart Kevin\OneDrive\Desktop\epomail` 运行。示例端口仅表示一个由维护者自行启动并确认的本地服务，本工具不会启动服务、构建、部署或修改配置。

```sh
node scripts/check-privacy-readiness.mjs --base http://127.0.0.1:8787
node scripts/check-privacy-readiness.mjs --base http://127.0.0.1:8787 --json
node --test tests/privacy-readiness.test.mjs
```

- 命令必须显式提供 `--base`，没有默认线上地址或环境变量回退。`--base` 必须是 origin，不能带用户信息、密码、路径（末尾 `/` 除外）、查询或片段。
- HTTP 仅允许 loopback，例如 `127.0.0.1`、`localhost`、`[::1]`；其他 HTTP 主机拒绝。HTTPS 仍须显式指定。只请求该 origin 下的 `/api/setting/websiteConfig`，不追随重定向，不抓取告知链接，不发送认证令牌或 Cookie。
- 网络请求连同响应读取最多 10 秒，不重试；请求失败退出 1。工具限制响应体积，校验成功响应封装及相关 URL，并对缺项、危险 URL、非布尔开关或不相容门槛给出字段级结果。
- 正常检查退出 0 只表示这一次响应通过配置检查，不是合规认证，也不是身份真实性证明或上线许可。`notReady`、格式错误、网络失败退出 1；`--help` 只显示用法，不运行检查。
- 输出不包含响应原文、联系资料、密码、secret 或原始异常内容。若要共享检查结果，也应先确认输出中没有另行添加的私人信息。
- API 无法证明 DPA/SCC 已成立、实际处理地区、供应商留存及删除、具体请求已执行，也无法证明页面可访问、后端门槛实际生效或真实身份正确。这些项目需要前述独立材料和验证。
- Node 测试仅使用注入的 `fetch` 和内存固定响应，不联网。合成夹具的就绪结果只验证工具分支，不会生成真实身份，不会签署合同，也不得导入运营配置充当通过证明。
