## 一、总体结论（TL;DR）

1. **修复方向正确、覆盖面广**：昨天审计的 P0×4 中 3 项已正确修复，P1×9 中 5 项已修复、3 项部分修复，P2×25 中 12 项已修复；登录应用删净 50 个 shadcn 死代码组件（−5723 行）。
2. **但批次是中断的**：P0-3 轮询重构在 5 个视图只删了 `try {` 没删配套的 `} catch (e) {...}`，**生产构建失败**（`views/all/index.vue:97` 等 5 处）；本次审计按 all-email 视图的正确迁移形态（composable 自带 401/403 兜底）完成了机械修复。
3. **「总觉得有些地方不太合适」的三个实锤来源**：
   - 分包配置写在 `build.manualChunks` 顶层——**Vite 7 已移除该简写，被静默忽略**，入口 chunk 纹丝不动 1183 kB；移挂到 `rollupOptions.output` 后实降 **896 kB** 并拆出 element-plus/echarts/vue-vendor 三个缓存友好 chunk；
   - 移动端抽屉会被**任意 resize 事件砸关**（软键盘弹出/地址栏收展即触发），用户永远怀疑"抽屉坏了"；
   - 桌面端汉堡按钮因 CSS 特异性冲突**在 1280px 桌面可见**，与"仅移动端显示"的设计意图相悖。
4. **移动端仍剩两个真问题**：375px 列表行主题仅 30px 宽（P1-2 修复不达标）；顶栏总宽 400px > 375px，**头像完全出屏**（x=448），用户在手机上无法进入头像菜单（退出登录/设置入口丢失）。
5. P0-4（8.72MB chunk）只是**部分修复**：13 个常用国家本地直出，其余国家（印度/巴西/俄罗斯等覆盖全球近半人口）仍触发 8.72MB 的 country-state-city 懒加载，且该 chunk 仍随产物分发。

## 三、本次审计新发现与修复（F1–F4 已修复，F5–F10 待办）

### F1 [P0·构建中断] 5 个邮件视图悬空 catch，`vite build` 失败 —— 已修复
- 证据：`views/{email,all,spam,snoozed,trash}/index.vue` 各 1 处 `} catch (e) {`（email:117/all:121/spam:118/snoozed:118/trash:118 修复前行号），旧 `try {` 已删而 catch 块残留；`npx vite build` 报 `Unexpected token, expected ","`。
- 原因：P0-3 重构把 `while(true)` 循环体机械搬进 `tick` 时中断，搬运未完成。
- 修复：按 `views/all-email/index.vue` 的正确迁移形态对齐（无内层 try/catch，401/403 由 `use-email-polling.js` 的 composable 统一兜底），并清理错乱缩进；修复后构建 24.9s 通过。

### F2 [P1·分包无效] `build.manualChunks` 在 Vite 7 被静默忽略 —— 已修复
- 证据：`vite.config.js` 将 `manualChunks` 写在 `build` 顶层；本机 vite@7.1.5 全部运行时/类型文件中 `manualChunks` 仅存在于警告文案（`node_modules/vite/dist/node/chunks/dep-M_KD0XSK.js:5454`），**顶层简写已随 Vite 7 移除**，键名不校验故无任何报错；产物实测无 `element-plus-*/echarts-*/vue-vendor-*` 命名 chunk，入口仍 1183 kB。
- 修复：移挂 `build.rollupOptions.output.manualChunks`（注释说明 Vite 7 挂载点）。重建后入口 **895.79 kB (gzip 303 kB)**，`element-plus-DYxc-xQq.js` 594.86 kB、`echarts-Np9APUFJ.js` 543.27 kB、`vue-vendor-Coz7PjHv.js` 287.35 kB 独立缓存，index.html modulepreload 仅 vue-vendor+element-plus。
- 残留建议：入口 896 kB 中图标离线注册表（`src/icons/index.js` 约 170 KB）与 6 语言 i18n 字典占比高，可作为下一批拆分对象（i18n 可按语言动态 import）。

### F3 [P1·移动端] 任意 resize 强制砸关抽屉 —— 已修复
- 证据：`layout/index.vue` `handleResize` 原实现 `uiStore.asideShow = window.innerWidth > 1024` 绑定在 `window.resize`——移动端**任何** resize（软键盘弹出、地址栏收展、旋转）都会把抽屉瞬间砸关。实测中抽屉在打开后被 resize 事件立即关闭，与"状态 OPEN 但截图无抽屉"的表象互相印证。
- 说明：修复批次只改了 `layout/aside/index.vue` 的 handleResize（跨断点才同步），漏掉了 `layout/index.vue` 这处同型缺陷。
- 修复：改为仅跨断点同步（`if (mobile !== isMobile.value) uiStore.asideShow = !mobile`），与 aside 侧修复模式一致。修复后抽屉打开状态在 resize/截屏扰动下保持稳定（Pinia `$subscribe` 插桩 2.5s 观测无复位）。
- 关联确认：`router/index.js:321-323` 在 afterEach 中 `innerWidth < 1025 → asideShow = false` 属导航后收起抽屉的合理 UX，保留。

### F4 [P2·桌面] 汉堡按钮 CSS 特异性冲突，桌面 1280px 仍可见 —— 已修复
- 证据：`layout/header/index.vue` 中 `.mobile-menu-btn { display: none }`（869 行）声明早于 `.icon-btn { display: flex }`（1020 行），同特异性下后者胜出；实测 1280px 视口计算样式 `display: flex`（截屏可见 ☰ 与 Logo 并列）。
- 修复：两条规则改用 `button.mobile-menu-btn` 前缀提升特异性（与声明顺序解耦）。重建后 1280px 实测 `display: none` ✓，375px 显示 ✓。

### F5 [P1·移动端·残留] 375px 列表行主题仍仅 30px 宽（P1-2 修复不达标）
- 证据：实测 `.email-subject-text` 宽 **30px**（"🎉 欢迎来到 Epocanvas Mail…"不可读）；现方案为单行内重分配（发件人 `max-width: 42%` + 摘要隐藏 + 主题 `flex-grow`），但发件人 + 时间 + 星标 + 间距吃掉行宽后主题所剩无几。
- 建议：按基线建议改为真两行布局（第一行发件人+徽章+时间，第二行主题独占），仅 `<768px` 生效；email-scroll 行结构需加一行容器，属小改。

### F6 [P1·移动端·新发现] 375px 顶栏溢出，头像完全不可达
- 证据：实测 `.topbar-actions` 宽 190px 且整体 x=190..380+，头像元素 x=**448**（viewport 375）——品牌文字+汉堡+动作图标排不下，头像菜单（退出登录/个人设置）在手机上**没有任何可达入口**。
- 建议：`<768px` 隐藏 `.brand-name` 文字与 Help 按钮、压缩图标间距（预计可省 ~110px），或将头像移入抽屉；同时给 `.topbar` 加 `flex-wrap`/最小宽度防御。

### F7 [P0→P1·部分修复] country-state-city 8.72MB chunk 仍在产物中
- 证据：`utils/geo-data.js` 新增 `LOCAL_INTL_SUBDIVISIONS` 13 国（US/CA/GB/AU/NZ/JP/KR/DE/FR/ES/IT/NL/MY）本地直出 ✓，但 `geo-data.js:253` 保留 `import('country-state-city')` 后台预取，未列出国家（IN/BR/RU/ID/VN/MX…）选择时仍拉满 8,716 kB；构建产物 `assets/index-Cm1Vkz8y.js` = 8,716.49 kB 仍在分发。
- 建议：彻底删除该依赖（`package.json` 一并移除），未列出国家回退为"仅国家无省州"或自建按需 JSON 资产（SW 缓存）；依赖的 8.7MB 数据只为低频的省州下拉，性价比极低。

### F8 [P2] 登录应用错误反馈细节
- 裸协议键：邮箱/密码为空提交时页面直接显示 `emailAndPwdEmpty`（错误码未映射文案，实测截获）；
- zh 浏览器下「会话过期」提示呈英文（"Your session has expired. Please sign in again."未走 `isZh` 回退）；
- 错误/成功提示为普通 `generic` 节点，无 `role="alert"`/`aria-live`，读屏不播报。
- 建议：错误码统一映射进 `i18n` 对象（顺带按 F9 收敛 isZh）；提示节点补 `role="alert"`。

### F9 [P2·残留] a11y 与样式债（本批次未触碰，维持基线判断）
- `aria-*` 16 处仍低；Esc 键退出仍仅 2 处；`!important` 1807 / 内联 style 640 / 硬编码色值 956 未见净下降；图标 14 套混用；sys-setting 9489 行未拆。均属路线图第二/三批，维持原建议。
