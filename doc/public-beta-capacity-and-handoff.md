# 公测交付与本轮验收

本轮从 GitHub 修复分支 `fix/public-beta-audited-20261120` 的 `468a4369e1373662da2f7234ce9c9dcedf7c2299` 开始。新增索引迁移为 `v3_30DB`。同步目标为这条修复分支。发布负责人在全部门禁通过后冻结 release 分支。

## 代码及测量

- 邮箱列表把分页、总数与到期公告检查组成同一 D1 批次。有到期公告时先执行清理再查。保留最新邮件、游标、已删除别名过滤及旧密文读取。侧栏计数与标签聚合合并读取。可见内容为明文时跳过邮箱密钥派生。每页一次导入邮件标识签名密钥，每条标识仍有随机盐并绑定用户。
- 认证保留逐请求的撤销和当前账号检查。同一请求只查一次撤销状态，跨日会话刷新使用本次 D1 核实的角色，多设备刷新批量核验。
- 发件先验证权限与内容指纹，恢复同键任务。新邮件取回实际归档 ID，无附件时减少附件查询；故障恢复、并发竞争、供应商结果未知和存量归档分别保留处理。站内投递通过索引查收件人，直接取得已提交邮件的 ID。原子配额判断同时计算容量和数量，个人通知关闭时跳过资料读取。
- 新索引仅在邮件库创建，支持按用户翻页、星标、存活公告到期和稀疏标签。上线前在脱敏的大库快照上记录创建耗时、空间增长与写入 P95，确认迁移重跑和旧 Worker 能操作新库。
- 同等比较用相同的单库临时环境、归档 Worker 和原有混合操作、阈值。诊断命令 `node tests/profile-backend-requests.mjs` 与正式容量测试分开。调用次数为每个 HTTP 请求的实际绑定调用；批语句计一次调用。SQLite 虚拟机指令与顺序请求计数均不能代表并发吞吐。
- 基线每轮 8 个业务操作、11 个 HTTP 请求，实测 137 次 D1 调用，执行 163 条 SQL。32 并发须在 10 秒内完成至少 960 个业务操作。原先两次为 544、548。本轮同一旧归档再测为 468；共享环境运行间存在差异。新包的实际报告与制品摘要一同交付。
- 公测修复分支、main、master 和 release 分支的推送或手动触发 Quality Gates 时，必须对 CI 实际归档执行 15 分钟有限负载及两次独立容量运行，保存每份 JSON。正式门禁依据每一轮的阶段样本、错误、合约、延迟和清理结果。CI 的归档摘要发生变化时，重新做绑定该归档的验证。

## 放行顺序与验收责任

| 顺序 | 负责人 | 操作与完成标准 |
|---|---|---|
| 1. 版本同步 | 仓库维护者 | 核对下载 ZIP 摘要、包内 SHA256SUMS、Git bundle 的基线与 tip。从自己的干净工作树 fast-forward 到交付 SHA 后正常推送修复分支。读取远端分支 SHA 与本地 HEAD，确保相同。分支已推进则先审查分歧并为合并结果重做全部验收。 |
| 2. 历史凭据 | 安全与邮件服务负责人 | 原候选全历史命中 15 个指纹，本轮已核实 3 个非秘密（2 个退役样例摘要及 1 个 UI 占位符）。剩余 12 个按指纹处置；每个指纹的存在不等于有一个独立有效密钥。用验证过的 gitleaks v8.24.3 对完整历史运行全量脱敏扫描。把每个指纹和有效范围交给相应账户所有者核实，轮换可能有效的 Mailjet、开发及测试环境密钥等，核对访问日志及旧值注销的供应商凭据标识和时间。只记录指纹、工单和证明。已证实的非秘密用精确指纹说明理由。任何真实凭据的历史处置另行审批；仅工作区或增量扫描通过不能关闭本项。 |
| 3. 容量与持续集成 | 后端、QA | 以相同 SHA 和归档通过 Worker、Node、前端、冷启动、真实浏览器、登录和隐私测试。检查两次 ramp-32 各自≥960/10s，15 分钟稳定性、重放幂等性与队列恢复。若仍不足，记录分操作吞吐、长尾和主机规格，拆分较慢的投递事务及配额扫描，在独占固定规格 runner 做优化前后对照，要求两轮均通过。 |
| 4. 受保护 Staging | 发布、SRE、QA | 记录同一 SHA、部署归档 SHA-256、Version ID、Deployment ID。以两个受控外部邮箱验证 MX 实收、真实投递、附件摘要、SPF/DKIM/DMARC、签名回执去重及延迟回执。验证注册、账号恢复、撤销、跨账号隔离、旧数据迁移，独立第三方配置仅在相应功能开启时验收。 |
| 5. 容量与运维 | SRE | 在 Staging 使用隔离账号验收 30 分钟代表性读、登录、写入和附件负载。建议首批范围 100 个邀请、20 个活跃并发；读 P95≤2 秒、登录 P95≤3 秒、无意外 5xx/超时，队列在 15 分钟内排空。验证 5 分钟 Cron 连续三次及一次夜间任务，确认漏心跳告警到达。记录备份及恢复，Worker 回退≤15 分钟、全量恢复 RTO≤60 分钟、RPO≤15 分钟。 |
| 6. 放行和回退 | 独立审批人、发布负责人 | 用实际证据填入 release 流程，必须得到 GO_PUBLIC_BETA。先按邀请限定规模开放，观察 24 小时后复核。发现跨账号泄露、非预期外发或邮件丢失立即停止放量；核心链路 5 分钟 5xx 超过 1% 或探针连续失败三次时暂停。通过已验证的上一 Worker 版本回退，核对队列、回执与迁移兼容性，保护投递记录。 |

实际下载包附本地验收报告。拥有云端权限的维护者在受保护环境中完成凭据轮换和 Staging 验收；敏感凭据及原始邮箱内容均不进入报告。完整表单和生产指令见 `doc/release/PUBLIC-BETA-EXECUTION-PLAN.md`、`doc/release/PUBLIC-BETA-PROMOTION.md` 及 `doc/public-beta-release-operations.md`。
