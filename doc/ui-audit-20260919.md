# EpoMail UI 全面审计报告（2026-09-19）

> 审计范围：`mail-vue`（主应用）、`temp_login_ui`（登录应用）、共享布局与样式体系。
> 审计方式：本地全真栈（`wrangler dev --config wrangler-dev.toml`，全新构建产物）浏览器实测 + 全仓静态扫描，只读，未改动任何业务代码。
> 视觉核验覆盖：登录页（桌面）、登录流程、收件箱（明/暗）、读信视图、写信弹窗、常规/安全/系统设置、分析页、角色管理、个人主页（明/暗）、375px 移动端（列表 + 读信 + 侧栏可达性）。

---

## 一、总体结论（TL;DR）

产品整体视觉品质高于同类自托管邮件项目：暗色模式完成度高、隐式 Tooltip 体系（227 处）贯彻到位、邮件列表有骨架屏与空态、路由 100% 懒加载、Element Plus 按需引入。**但存在四个必须优先处理的 P0 问题与一批系统性的结构问题**：

1. 登录页存在「随机行星撞击 → 全屏红/白闪光警报」特效，有光敏性癫痫风险（WCAG 2.3.1）且与邮件产品语义无关；
2. 登录页「保持轨道连接」复选框是假的——无论勾不勾，邮箱都会写入 localStorage，公共设备有隐私残留；
3. 6 个邮件视图各自持有 `while(true)` 轮询死循环，后台不暂停、永不终止、`autoRefresh=0` 仍每 3 秒空转；
4. 个人资料页触发一个 8.72 MB 的懒加载 chunk（country-state-city 全量国家/州/城市数据），移动端近乎不可用。

「感觉有些地方不太合适」的直觉主要来自四类系统性问题：**移动端导航/写信完全不可达、登录↔主应用语言与设计语言断层、图标体系 12+ 套混用、样式体系以 1803 个 `!important` 硬扛而非设计令牌**。

## 三、P0 发现（建议立即处理）

### P0-1 登录页「行星撞击」随机全屏红/白闪光警报
- 证据：`temp_login_ui/src/app/components/epomail/PassingPlanets.tsx:97-129,224`（行星 10% 概率"命中"，命中时 `warningOpacity=1`，pass-through 场景 `overlayOpacity=1` 全屏纯色闪屏）；`App.tsx:129-181`（红色 HUD `WARNING / IMPACT DETECTED / HULL INTEGRITY COMPROMISED` + `animate-ping` 闪烁 + 镜头抖动）。实测登录页可访问性树中出现这些 HUD 文本节点。
- 为什么不合适：① 光敏性癫痫风险（WCAG 2.3.1 三次闪光阈值）；② 用户正在输密码时全屏变红/白 + 抖动，属于惊吓而非愉悦；③ 与"邮件"产品毫无叙事关联；④ 夜间体验差。
- 建议：登录场景整体移除撞击/警报系统，或降级为无闪屏的纯装饰（行星飞过即可）；至少让 `hitType` 全部 miss，并提供「静简模式」开关。同时这些 HUD 文本必须 `aria-hidden`。

### P0-2 「保持轨道连接」复选框无效 + 邮箱无条件落地 localStorage
- 证据：`AuthForm.tsx:693`（checkbox 无 `checked`/`onChange`，纯装饰）；`:277,316`（登录成功时**无条件**写 `loginEmail`）；`:174-180`（挂载时无条件回填）。
- 为什么不合适：勾不勾结果一样，是功能欺骗；公共电脑上邮箱永远残留，隐私风险。
- 建议：绑定受控状态，仅在勾选时持久化；未勾选时登录成功即清除；提供「清除记住的邮箱」入口。

### P0-3 邮件轮询：6 份 `while(true)` 死循环、后台不暂停、永不终止
- 证据：`views/email/index.vue:53,77-126`、`views/all/index.vue:51,81`、`views/spam/index.vue:54,78`、`views/snoozed/index.vue:54,78`、`views/trash/index.vue:54,78`、（管理视图）`views/all-email/index.vue:170,425`。全 src 无 `visibilitychange` 处理（grep=0）；循环内仅靠 `if (route.name !== 'xxx') continue;` 空转；组件无 `onUnmounted` 终止。
- 为什么不合适：后台 tab 每 3 秒打一次服务器（耗电/流量/服务端负载随 tab 数线性放大）；用户每访问一个邮件页就永久多出一个死循环闭包（持有已卸载组件 ref，内存滞留）；`autoRefresh=0`（用户关闭自动刷新）仍每 3 秒醒一次。
- 建议：抽取单一 `useEmailPolling` composable（全局单例）：`document.visibilitychange` 暂停/恢复、`onUnmounted` 终止、`autoRefresh=0` 彻底停止。

### P0-4 个人资料页触发 8.72 MB 懒加载 chunk
- 证据：产物 `mail-worker/dist/assets/index-Cm1Vkz8y.js` = 8,716,486 B，内含 country-state-city 全量国家/州/城市/时区 JSON；链路 `views/profile-info/index.vue:499-500` → `utils/geo-data.js:231` `import('country-state-city')`。
- 为什么不合适：动态 import 只是"延迟到进入页面"，仍是一次性整包下载；个人资料编辑页在弱网/移动端近不可用；与代码注释宣称的 "loaded on-demand for zero initial lag" 相悖。
- 建议：`utils/geo-data.js` 本地已有 16KB 精简数据兜底，可彻底移除该依赖；或改用按国家惰性拉取的单国子集 + SW 缓存。

## 四、P1 发现（明显不合适，尽快安排）

### P1-1 移动端（<768px）侧边栏、写信、文件夹导航完全不可达
- 实测：375px 视口下，点击 Logo 图标无反应、点击标题文字跳转个人主页、左缘滑动手势无响应；顶部无汉堡图标；写信按钮只存在于不可见的侧栏内。用户被困在列表页。
- 代码证据：`components/hamburger/index.vue` 存在但在 `layout/header/index.vue:102` 以 **拼写错误的 `import hanburger`** 引入后从未在模板渲染（死代码）；`layout/aside/index.vue:204` 的 `isMobile = ref(window.innerWidth < 1025)` 只在挂载时取值一次；`layout/main/index.vue:125` 的 `computed(() => window.innerWidth < 768)` 无响应式依赖，跨断点缩放窗口后状态冻结。
- 建议：恢复汉堡按钮渲染（移动端显示、桌面隐藏）；抽屉式侧栏 + 遮罩；移动端列表底部加悬浮写信 FAB；`isMobileView` 改用 `useWindowSize()`（VueUse 已在依赖中）。

### P1-2 移动端列表行主题被挤压至不可见
- 实测：375px 列表行只显示发件人 + 表情符号 + "..."，主题与摘要完全不可读，多封邮件无法区分。主题文本在 DOM 中存在（`components/email-scroll/index.vue:122-128` subject+snippet 单行内联截断），窄屏下发件人与徽章占满行宽后主题被 ellipsis 到归零。
- 建议：窄屏断点改为两行布局（第一行发件人+时间，第二行主题），摘要仅在 ≥768px 显示。

### P1-3 登录 ↔ 主应用的语言与设计语言双重断层
- 语言：登录页按 `navigator.language` 渲染（实测中文），登录成功进入主应用后默认 `setting.lang=en`（实测 localStorage `{"lang":"en"}`），中文用户从中文登录页跌进英文收件箱。登录应用自身是 96 处 `isZh` 三元表达式硬编码（`AuthForm.tsx:143-146` 等），繁体用户在登录页看到简体，而主应用有完整 zh-Hant 包；fr/es/nl 用户登录页一律英文。
- 设计语言：登录页是深空玻璃拟态 + 游戏化 HUD（Space Grotesk/Inter 字体、浮动标签输入框），主应用是 Element Plus 标准控件（Outfit 字体、边框输入框、ElMessage 提示）。登录成功 800ms 后硬跳 `/inbox`（`AuthForm.tsx:288-290`），体感断裂。
- 建议：① 登录成功携带语言偏好写入 `setting.lang`（或初始化时同源读取）；② 登录应用抽 `useAuthI18n()` 统一 hook，对齐主应用六语言清单；③ 输入框、按钮、Toast 视觉向主应用靠拢（保留星空背景即可）。
- 关联缺陷：`AuthForm.tsx:210-231` 用 `rawMsg.includes("过期")` 等中文子串匹配后端错误消息来决定提示文案——后端文案即协议，改写即失配；应改为错误码映射。

### P1-4 可访问性系统性缺失
- 实测可访问性树：顶栏 4 个图标按钮（搜索/主题/帮助/通知）全部无可访问名称（有 tooltip 但触发器无 `aria-label`）；侧边栏全部导航项（Main/Starred/.../Labels）是可点击 `generic` 而非 `link/button` 角色，键盘用户无法 Tab 到达；邮件行把**整封邮件正文**塞进可访问性树（列表行 snippet 在 DOM 中未截断，读屏用户要听完整封欢迎邮件）；全应用 `aria-*` 仅 8 处。
- 建议：① 图标按钮统一补 `aria-label`（可在封装 tooltip 时同时写入）；② 侧栏导航语义化（`nav` + `a`/`button`）；③ 列表行 snippet 在数据层截断到 ~140 字符再入 DOM；④ 行/导航补 `role` 与 `tabindex`。

### P1-5 样式体系：1803 个 `!important` 硬扛，而非令牌化
- 证据：sys-setting 729 个、style.css 586、tiny-editor 204；模板内联 style 641 处；硬编码色值 954 处绕开 style.css 已有的 CSS 变量体系。这是「改一处崩三处」、暗色模式需要逐处打补丁的根源（style.css 里 73 个 `html.dark` 选择器大多是在给硬编码色值擦屁股）。
- 建议：不搞一次性大重构，立规矩渐进治理：新代码禁止新增 `!important`/内联 style/硬编码色值；每触碰一个组件就顺手令牌化；Element Plus 覆盖统一走 `:deep()` + 变量覆盖层，而不是 `!important` 竞赛。

### P1-6 图标体系 12+ 套混用
- fluent 278 / lucide 81 / fe 62 / solar 28 / ri 26 / material-symbols-light 21 / ion 14 / ic 14 / simple-icons 12 / iconoir 11 / uiw 7 / hugeicons 7……同一页面线性图标与双色图标混排，粗细与圆角风格不一致（实测系统设置页「Static UI」分段控件中的图标形似"破图占位符"，即选型不当的直观案例）。
- 建议：收敛为 fluent（界面）+ simple-icons（品牌）两套；写一个 codemod/检索清单分批替换。

### P1-7 登录页假功能与死链
- `AuthForm.tsx:696-702` 忘记密码 `href="#"` 无任何行为；`:758-772` Google/GitHub 按钮无 onClick、后端亦无对应 API，点击毫无反馈。
- 建议：未实现的入口先移除（或点击给出"未开放"提示），上线即负债。

### P1-8 首屏 1.18 MB 单 chunk、无分包
- 证据：入口 `index-BVTdQzsf.js` 1.18 MB / `index-Db2ALrEE.css` 474 KB；`vite.config.js:54-59` 无 `manualChunks`、无 `chunkSizeWarningLimit`（devDeps 装了 terser 未用）。
- 为什么不合适：任何业务改动都使整个 vendor chunk 缓存失效；首屏解析时间长。
- 建议：`manualChunks` 拆 vue-core / element-plus / 图标注册表（`src/icons/index.js` 1502 行离线注册表约 170 KB，可评估按需化）/ 六语言 i18n。

### P1-9 `prefers-reduced-motion` 覆盖点状、系统性缺失
- 全仓仅 3 处：`mail-vue/index.html:255`（首屏 loading）、登录应用 `CanvasBackground.tsx:126-128`（仅背景星空）、`theme.css:245-249`（覆盖的是未使用类）。行星撞击、3D 视差、震屏、主应用运行期动画均不受控。
- 建议：两应用各在根组件读取一次 `prefers-reduced-motion`，注入全局开关；装饰性动画（视差/震屏/循环 glow）统一受控。

## 五、P2 发现（打磨项）

### 视觉/交互
1. **登录页 Logo 背后矩形亮块未融合**：卡片顶部 Logo 后有一块边缘生硬的矩形亮区，压过卡片圆角边框（实测截屏确认）。建议裁切进卡片圆角或改为径向光晕。
2. **登录页生产标题为 Figma 模板残留**：浏览器标签显示 "Login Screen UI Layout Plan"（`temp_login_ui/index.html:8`）。应改为产品名。
3. **登录表单标签样式不一致**：邮箱字段用悬浮标签（青色「邮箱地址」），密码字段用占位符（「登录密码」），同屏两种范式。
4. **读信视图无独立路由**：读信时 URL 仍为 `/inbox`，刷新即丢阅读态、浏览器后退直接退出应用。建议 `/inbox/:emailId` 路由化或至少 `history.pushState`。
5. **设置表单布局失衡**：标签列窄导致「Translation Target Language」等英文标签 2~3 行换行，控件列右侧一半卡片空白（实测常规设置页）；Bio 卡片整卡仅一行内容，留白失衡。建议标签列加宽 + 控件列弹性撑满。
6. **安全设置页 CTA 重复**：同一屏出现两颗「Set up 2-Step Verification」按钮（横幅大按钮 + Authenticator App 行内按钮）。
7. **分析页图表配色不搭**：Email Source/Source Distribution 用 echarts 默认蓝（#3b9eff 系），与全站紫/靛主题色冲突；Donut 图直径偏大撑高卡片；「User Growth」空数据无任何空态提示（同页 AI Usage 却有 "No AI call records yet"），空态策略不一致。
8. **角色表格横向截断无提示**：1440px 下 Description 列被硬裁，最右还露出半截彩色元素，无渐隐遮罩或滚动提示；「Attachment Permission」列全员为空仍占位。
9. **个人主页小瑕疵**：Source Distribution 的 "100%" 文本与卡片右缘相撞；Email Processing Trends 的零基线悬浮在图表中部，柱子向下生长，视觉困惑。
10. **移动端状态栏重叠**：375px 下底部状态栏「Privacy Mail Mode」徽章压住「EpoMail v1.1.0 · Cloudflare Workers」文字（实测截屏）。
11. **移动端读信工具栏拥挤**：10 个图标按钮挤满 375px 单行，最右侧翻译图标被裁切。
12. **列表工具按钮居中摆放怪异**：收件箱顶部「排序/刷新」两个图标孤悬于列表区正中，不符合左操作右状态的惯例。
13. **自定义视图基本无 Esc 退出**：全 src 仅 2 处键盘退出处理；全屏读信/写信层应支持 Esc。
14. **邮件行 checkbox 无可访问名称**（全选与单选均无名）。

### 架构/工程
15. **巨型组件**：sys-setting 9489 行（单文件 168 处内联 style + 729 个 `!important`）、data-setting 3072、role 2235、content 2226。建议按卡片/弹窗拆子组件。

18. **`/test` 空壳路由暴露生产**（`router/index.js:197-199`）。
19. **Windows 下 `npm run build` 直接失败**：`mail-vue/package.json:9` 用 `cp -r`（cmd 无此命令，Git Bash 可用）。建议改 Node 脚本或 `shx`。
20. **登录应用大量死代码**：`src/app/components/ui/` 50 个 shadcn 组件约 5000 行零引用；package.json 中 `@mui/*`、`recharts`、`react-dnd`、`react-slick`、`canvas-confetti` 等依赖无引用；`NodeGlyph.tsx` 未使用；`PassingPlanets.tsx.patch` 补丁残留；`LoginCard/RegisterCard` 131 行近乎全同；`FloatingField` 双份实现。
21. **`websiteConfig` 一次注册流程请求 3 次**（`App.tsx:20-29`、`App.tsx:49-56`、`RegisterForm.tsx:136-145`）。
22. **登录页外部 Google Fonts `@import`**：渲染被第三方字体请求阻塞，有隐私/合规顾虑，建议自托管 woff2。
23. **特效色值传参 bug**：`AuthForm.tsx:300-302`、`RegisterForm.tsx:248,288-290,319` 传 `#eab308`/`#22c55e`，而 `pickColor`（`CanvasBackground.tsx:45-52`）只认 purple/cyan/indigo 枚举，非法值静默随机——错误/成功提示的粒子颜色从来不是调用方想要的黄/绿。
24. **登录页星空粒子密度过高**：`(w*h)/75` ⇒ 1080p 约 2.7 万颗星、每帧 2.7 万次 `ctx.stroke()`（`CanvasBackground.tsx:139,292-318`）。建议密度降 1~2 个数量级或按 `hardwareConcurrency` 自适应。
25. **仓库根目录卫生**：根目录堆积 60+ 一次性脚本、截屏、mockup HTML（`patch_agents*.js`、`ss-*.png`、`login_shot_*.png`、`test-hash2.js` 等），建议归档到 `doc/archive/` 或删除，`.gitignore` 增加产物类规则。
