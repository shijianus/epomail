EpoCanvas Mail（下稱「本服務」或「本軟體」）是一個基於 Cloudflare 全家桶（Workers、D1、KV、R2）建置的**開源電子郵件服務**，以 MIT 授權條款發布。它既可以作為公開的託管信箱網站運作（例如 `mail.epocanvas.com`），也可以由任何人自行部署為私有郵件服務。

我們撰寫這份政策的目的很簡單：**用一般人看得懂的話，講清楚您的資料去了哪裡、誰看得到它、您能對它做什麼。** 我們不投放廣告、不追蹤使用者、不出售資料——以下每一節都會具體解釋這句話的意思。

:::note[30 秒快速摘要]
- **我們蒐集**：您的電子郵件地址、密碼（只保存加鹽雜湊，任何人——包括營運者——都無法還原您的原始密碼）、您收發的郵件內容與附件、登入 IP 與設備資訊。
- **我們不會拿它做什麼**：不投放廣告、不賣給任何第三方、不接入任何統計／埋點服務。
- **誰在負責**：您所用實例的營運者（站長）是您資料的「資料控管者」。EpoCanvas Mail 作為開源軟體本身不蒐集、不上傳任何資料。
- **您隨時可以**：一鍵匯出全部郵件（JSON）、刪除郵件與帳號、開啟兩步驟驗證、撤銷第三方應用授權。
- **需要留意的第三方**：當您主動點擊「翻譯」時，郵件文字會被傳送給您實例所設定的 AI 翻譯服務；當營運者開啟寄出投遞時，站外郵件會經由 Resend 或 Mailjet 傳送。詳見[第 6 節](#6-第三方服務與資料共享)。
- **遇到不熟悉的詞**：請翻到文末[附錄 B：關鍵術語表](#附錄-b關鍵術語表)，每個術語都配了一句白話解釋。

## 2. 我們蒐集的資訊

和多數網路服務不同，我們想讓您在閱讀細節之前先有一個整體印象：本服務**只蒐集把郵件送達您所必需的資訊**，並刻意繞開了廣告生態依賴的一切採集手段。依照資料進入系統的方式，分為三類。

### 2.1 您主動提供的資訊

- **電子郵件地址**：即您的帳號識別（形如 `you@example.com`）。使用者名稱預設取信箱前綴，與同站已有使用者名稱衝突時自動改用完整信箱地址區分。
- **密碼**：僅以 **PBKDF2-HMAC-SHA256（100,000 次迭代 + 每使用者獨立隨機鹽）** 的加鹽雜湊形式保存。這是單向變換，連營運者也無法從資料庫還原您的原始密碼。
- **兩步驟驗證憑證（選填）**：若您啟用 TOTP 動態密碼，密鑰會以 AES-256-GCM 加密儲存；備用復原碼只保存 SHA-256 雜湊；若您登記通行密鑰（Passkey），只保存公鑰。
- **個人資料（選填）**：暱稱、頭像、個人簡介等。頭像圖片會上傳至營運者設定的圖片儲存服務。

### 2.2 您的郵件內容

您透過本服務收發的郵件，包括寄件人、收件人、主旨、內文、時間等中繼資料，以及您對郵件施加的標籤、星號、已讀狀態、延後提醒，均會保存在實例的資料庫與物件儲存中。附件檔案保存於 Cloudflare R2、營運者設定的 S3 相容儲存（如 Backblaze B2），或作為備援存入 KV。

### 2.3 自動蒐集的技術資訊

- **登入與註冊紀錄**：每次註冊、登入會記錄 IP 位址與瀏覽器 User-Agent，並從中解析出作業系統、瀏覽器與設備類型。這些資訊用於安全稽核（例如識別異常登入）與配額控制。
- **工作階段權杖**：登入成功後簽發的 JWT（有效期 30 天）保存在您瀏覽器的 localStorage 中。本服務**不使用 Cookie**，也不存在跨站追蹤 Cookie。
- **請求中繼資料**：底層基礎設施（Cloudflare）會在其邊緣網路處理請求，並可能依其自身政策記錄連線中繼資料與執行日誌。

### 2.4 我們刻意不蒐集的東西

以下清單和蒐集清單同樣重要：

- ❌ **無廣告追蹤**：沒有廣告 SDK、沒有行為畫像、沒有跨站 Cookie。
- ❌ **無第三方統計**：不接入 Google Analytics、Plausible 或任何埋點服務。
- ❌ **不出售資料**：任何情況下都不會將您的資料出售、出租或用於廣告交易。
- ❌ **無密鑰回傳**：開源軟體不會向上游作者或任何第三方「回報」您的實例資料。您部署的實例資料完全留在您自己的 Cloudflare 帳號裡。
- ❌ **無後台越界採集**：系統不會讀取您裝置上的通訊錄、相簿、位置或其他應用程式資料；「技術資訊」僅限於上述與請求和工作階段直接相關的欄位。

## 5. 資料儲存、加密與安全

### 5.1 存在哪裡

所有資料保存在實例營運者自己的 Cloudflare 帳號內：結構化資料（使用者、郵件、設定）存於 D1（SQLite）資料庫，快取與工作階段存於 KV，附件存於 R2 或 S3 相容儲存。EpoCanvas Mail 的上游開源作者**不持有、也接觸不到**任何實例的資料。

### 5.2 三種郵件模式下的加密

本服務提供三種儲存模式，由實例營運者選擇：

| 模式 | 郵件儲存狀態 | 誰能讀到您的郵件 |
| --- | --- | --- |
| **全部郵件模式** | 明文儲存 | 營運者（管理員）可以讀取全部使用者郵件 |
| **隱私模式**（預設） | 正常郵件以 AES-256-GCM 靜態加密 | 管理員僅能接觸垃圾郵件、已刪除與無主郵件，不能翻閱您的正常收件匣 |
| **加密模式** | 包括垃圾筒在內的全部郵件均加密 | 管理員後台的郵件管理介面不回傳任何使用者郵件 |

:::caution[誠實的加密邊界說明]
上述加密是**伺服器端靜態加密**：加密密鑰由實例伺服器上的環境變數與您的使用者識別衍生。這表示**掌握伺服器與密鑰的營運者在技術上具備解密能力**——它防範的是資料庫檔案被直接拖走、快照洩漏等情境，而**不是**端對端加密（E2EE），營運者並非絕對無法讀取。如果您需要的是連營運者也無法讀取的零知識隱私，請勿依賴任何信箱服務的加密模式，而應使用專門的端對端加密工具（如 GPG）先加密郵件內文再寄出。
:::

### 5.3 傳輸與存取安全

- 全站強制 HTTPS/TLS；密碼重設、登入等敏感介面具備速率限制與失敗鎖定。
- 兩步驟驗證：支援 TOTP 動態密碼（RFC 6238）與 FIDO2 通行密鑰（Passkey／指紋／臉部辨識），強烈建議開啟。
- 工作階段管理：同帳號最多 10 個並行工作階段；您可以在任意裝置上登出，權杖即時吊銷。
- 管理員的特殊能力（如實告知）：依據角色權限，實例管理員可以重設使用者密碼、強制重設兩步驟驗證、封鎖或刪除帳號、檢視使用者的註冊 IP 與裝置清單，並在「全部郵件模式」下讀取使用者郵件。**選擇實例即選擇信任其營運者**——請像選擇信箱服務商一樣認真對待。

## 6. 第三方服務與資料共享

參照大型服務商的通行做法，我們把「資料離開實例」的情形歸納為四類，方便您快速判斷每一次共享的性質：

1. **基礎設施處理者**（全程在後台）：Cloudflare 為實例提供執行、儲存與網路，是所有資料的「地基」；
2. **經營運者設定的功能**（寄信時觸發）：出站投遞服務商替實例把郵件送到外部世界；
3. **經您主動觸發的功能**（您點擊才發生）：翻譯、圖片上傳、Telegram 綁定、Linux DO 登入；
4. **法律要求**：僅在依法定程序被要求時發生（見本節末尾）。

本服務的原則是：**能不出去的資料絕不出門；必須出門的資料，出哪一扇門、帶什麼東西，全部寫在下面這張表裡。**

| 第三方 | 角色 | 何時觸發 | 共享的內容 |
| --- | --- | --- | --- |
| **Cloudflare** | 基礎設施（執行環境、D1/KV/R2 儲存、郵件路由、人機驗證、Workers AI、日誌） | 全程 | 請求中繼資料、儲存內容、驗證碼校驗請求 |
| **Resend / Mailjet** | 站外郵件投遞服務商 | 僅當您寄送收件人在站外的郵件、且營運者設定了投遞通道時 | 完整郵件（收件人、主旨、內文、附件） |
| **Telegram** | 即時通知推送 | 僅當您（或營運者）綁定了 Telegram 機器人並開啟推送時 | 依設定推送：郵件主旨、寄件人（可隱藏）、內文（可隱藏）、驗證碼、郵件檢視連結（7 天有效） |
| **AI 翻譯服務**（實例設定的中繼端點、Cloudflare Workers AI、MyMemory、Google 翻譯公共介面） | 翻譯處理 | **僅當您點擊「翻譯」按鈕時** | 被翻譯的郵件文字（優先整段傳送；備援情境下為擷取的文字片段）；OCR 翻譯時包含圖片 |
| **圖片上傳服務** | 頭像與圖片儲存 | 僅當您上傳頭像等圖片時 | 圖片檔案本身 |
| **Linux DO** | 第三方登入身分來源 | 僅當您使用 Linux DO 帳號登入時 | OAuth 授權換回的使用者識別、暱稱、頭像、信任等級 |
| **Google Fonts** | 介面字型載入 | 瀏覽器載入頁面時 | 字型請求（您的 IP 會出現在 Google 的請求日誌中） |
| **您／營運者設定的 S3、Turso 等** | 外部儲存 | 僅當設定了外部儲存／資料庫時 | 附件或資料副本 |

:::tip[關於「不賣資料」的具體含義]
上表中沒有任何一家收到您的資料是為了廣告目的；我們與它們之間不存在任何資料售賣或廣告分成關係。其中部分服務（如 Cloudflare、Resend）以「處理者」身分依營運者的指令處理資料，各自受其自身隱私政策約束（您可在其官網查閱）。
:::

:::note[法律要求與監管合作]
除非法律強制要求或有權機關依法定程序提出請求，營運者不會主動向第三方揭露您的資料。如收到此類請求，營運者將核查其合法性、僅揭露法律要求的最小範圍，並在法律允許的範圍內通知您（除非被依法禁止）。自行部署營運者應按其所在轄區補充與執法機關合作的具體承諾。

## 7. AI 功能說明

本服務內建三類 AI 能力，觸發方式與資料邊界如下：

1. **驗證碼自動擷取**（營運者可選開啟）：新郵件送達時，系統自動把主旨與內文前 6000 字傳送給 Cloudflare Workers AI 擷取驗證碼，方便您在列表和 Telegram 通知中一鍵複製。這是唯一一個**不經您手動觸發**的 AI 處理，如不希望發生，請聯絡營運者關閉或選擇未開啟該功能的實例。
2. **郵件 AI 翻譯**（您主動觸發）：點擊「翻譯」後，郵件文字經分片傳送給實例設定的大型模型端點（預設相容 OpenAI 協定），並啟用多模型故障轉移；當模型不可用時，會備援呼叫 MyMemory 或 Google 翻譯公共介面補齊譯文。**不點擊即不發生**。
3. **圖片 OCR 翻譯**（您主動觸發）：對包含文字的圖片進行文字辨識並翻譯，圖片會傳送給上述 AI 服務；純裝飾圖、Logo、圖示會被自動跳過，不發生外傳。

AI 處理不用於訓練目的對接：系統不會將您的郵件用於訓練任何模型，也不向 AI 服務傳送除翻譯所需文字之外的使用者身分資訊。

## 8. 資料保留與刪除

| 資料 | 保留策略 |
| --- | --- |
| 正常收件匣郵件 | 保留至您手動刪除，或信箱用量超過配額觸發的清理 |
| 垃圾郵件 | 自動隔離 **7 天**後轉入垃圾筒 |
| 垃圾筒郵件 | 自收到之日起 **7 天**後由系統每日例行任務**物理刪除**（含附件二進位檔與索引） |
| 被刪除帳號的郵件 | 自助註銷為**軟刪除**：郵件在管理員執行物理刪除前仍保留於資料庫（技術上可被復原）；管理員執行物理刪除後，使用者資料、信箱、郵件、附件、OAuth 授權與工作階段將被徹底移除 |
| 登入紀錄（IP／UA） | 保存於使用者檔案，直至帳號被物理刪除 |
| 工作階段權杖 | 登出即從伺服器端吊銷；30 天未活動自然過期 |
| 實例停止營運時 | 營運者應提前通知並提供資料匯出窗口期；停運後資料隨實例的 Cloudflare 資源（D1/KV/R2）一併銷毀，不會被移交給無關第三方 |

:::caution[刪除前請先匯出]
物理刪除不可復原。如需帶走資料，請先使用「設定 → 資料匯出」匯出 JSON 副本（包含您的全部資料與未刪除郵件的完整內文）。
:::

## 9. 您的控制權與權利

無論您位於哪個司法轄區，本服務為您內建以下自助工具：

- **資料可攜權**：設定頁一鍵匯出全部個人資料與郵件（JSON 格式，明文可讀）。
- **刪除權（被遺忘權）**：可逐封刪除郵件（7 天後物理清除），可自助註銷帳號，也可要求管理員立即物理刪除。
- **存取與更正權**：您隨時可在設定中檢視並修改暱稱、頭像、語言偏好、收發信偏好等資料。
- **公開主頁開關**：個人公開主頁預設僅本人與管理員可見。開啟後，您的信箱地址、暱稱、頭像、註冊時間與收發統計將對公開網路可見——**是否公開完全由您決定**。
- **第三方授權管理**：您可以在「第三方應用」中檢視全部 OAuth 授權，並隨時一鍵撤銷；撤銷後對應存取權杖立即失效。
- **工作階段管理**：可在任意裝置登出以吊銷該裝置的權杖。
- **反對與退出**：可關閉 Telegram 推送、不點擊翻譯按鈕即可避免 AI 外傳、可選擇未開啟驗證碼識別的實例。

若您所在轄區（如歐盟／EEA、英國、加州）賦予您額外法定權利（申訴、限制處理等），請聯絡實例營運者行使；營運者負有在法定期限內回應的義務。關於回應時限，本服務承諾：**介面上的自助操作（匯出、刪除、撤銷授權、登出）即時生效**；需要人工處理的請求（如物理刪除），營運者應在 **30 天內**答覆並完成。若對處理結果不滿意，您還有權向您所在地的資料保護監管機關（data protection authority）申訴。

## 10. 通訊與通知

本服務本身不向您寄送行銷郵件。您可能收到的站內信件僅有：官方歡迎郵件、營運者發布的全站公告（二者由官方帳號 `admin@epocanvas.com` 站內直投，不經外部服務）、以及外部寄件人寫給您的正常郵件。Telegram 推送與轉寄到其他信箱的功能預設關閉，開啟後可隨時關閉。

## 11. 兒童與未成年人

本服務不面向 14 歲以下的兒童，營運者不會有意蒐集兒童的個人資訊。若您是兒童的監護人並認為您的孩子向我們提供了個人資訊，請聯絡實例營運者，核實後將立即刪除相關資料。自行部署營運者應根據其所在轄區與使用者族群，自行設定更高的最低年齡要求。

## 12. 國際資料傳輸

本服務建置於 Cloudflare 全球邊緣網路之上，資料可能儲存於營運者所選定的 Cloudflare 資料中心區域（D1/KV/R2 支援位置選擇），並經由全球任一邊緣節點傳輸。這意味著資料可能在其營運者所在國以外被處理。Cloudflare 已透過其合規架構（如 GDPR 下的標準合同條款）為資料傳輸提供保障，細節可查閱 Cloudflare 官方合規文件。使用託管實例即表示您理解並接受這一基礎設施特性。

## 13. 自行部署營運者指南

如果您把 EpoCanvas Mail 部署到了自己的網域下，那麼從法律與事實層面，**您就是您使用者的「我們」**。請完成以下動作：

1. **替換本檔案的佔位資訊**：聯絡信箱、實例名稱、生效日期，並複核第 6 節第三方清單（例如您沒有設定 Telegram 或 Resend，就刪掉對應列）。
2. **如實選擇並揭露郵件模式**：您選擇的「全部／隱私／加密」模式直接決定 5.2 節的表述是否成立。
3. **履行轄區義務**：若您的使用者涉及歐盟（GDPR）、英國、巴西（LGPD）、加州（CCPA/CPRA）等地，您可能需要補充合法性基礎、DPA（資料處理協議）、法定保留期限與本地申訴管道等條款。本檔案是工程團隊編寫的良好起點，**不構成法律意見**，上線前建議諮詢執業律師。
4. **保持零遙測承諾**：您基於本軟體的部署天然繼承「無統計、無上報」的底座；若您自行加入第三方統計，請在您的隱私權政策中如實揭露。

## 附錄 B：關鍵術語表

我們盡量不用行話；必須用到時，按下面的白話解釋理解即可。

| 術語 | 一句話解釋 |
| --- | --- |
| **帳號** | 您在某個實例上的身分，由信箱地址標識；密碼只以單向雜湊保存，誰也還原不了 |
| **實例（網站）** | 執行在某個人或團隊的 Cloudflare 帳號裡的一份 EpoCanvas Mail，例如 `mail.epocanvas.com` 或您公司自建的網站 |
| **營運者** | 部署並管理實例的人或團隊；對您的資料而言就是「資料控管者」，也就是本政策裡的「我們」 |
| **資料控管者 / 資料處理者** | 決定「為什麼收、怎麼用」的一方是控管者（營運者）；依其指令代為處理資料的一方是處理者（如 Cloudflare、Resend） |
| **內容資料** | 您收發的郵件內文、主旨、附件，以及您施加的標籤、星號、已讀狀態等資訊 |
| **技術資料** | 為執行與安全所需自動記錄的 IP、瀏覽器 User-Agent、裝置類型、登入時間等 |
| **localStorage（本地儲存）** | 瀏覽器提供的網頁資料儲存機制，資料保存在您的裝置上、可跨工作階段保留；本服務的登入權杖存於此處而非 Cookie |
| **工作階段權杖（JWT）** | 登入成功後簽發的「通行憑證」，30 天有效、同帳號最多 10 個並行、登出即吊銷 |
| **PBKDF2** | 一種密碼雜湊演算法；本服務以 10 萬次迭代加鹽處理，使原始密碼無法從資料庫反推 |
| **靜態加密（加密儲存）** | 資料落盤時的加密；本服務的密鑰由伺服器環境變數衍生，掌握伺服器與密鑰的營運者在技術上可解密 |
| **端對端加密（E2EE）** | 只有收發雙方能解密的加密方式；本服務**不提供**，如需此強度請自行用 GPG 等工具先加密再寄出 |
| **遙測（Telemetry）** | 軟體自動向開發者回傳使用資料的行為；EpoCanvas Mail 零遙測，不向上游回傳任何實例資料 |
